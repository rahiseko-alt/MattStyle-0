# f — セッション終了の儀式

利用者は非エンジニア。「もう閉じていいのか」を自分では判断できない。
このスキルが確認を代行し、**根拠つきで終了可否を宣言する**。

宣言は嘘であってはならない。1項目でも満たせないなら「終了して問題ありません」と言わない。

## 起動する場面

- 利用者が「f」「F」「/f」とだけ送ったとき

一文字の「f」が明らかに別の意味に見える場合は通常どおり応答する。
判断に迷ったときだけ「終了の合図でしょうか」と一度だけ尋ねる。

## 確認する4項目

上から順に片づける。**満たしていなければ、まず自分で満たしにいく。報告だけして終わらない。**

1. **手元の未保存の変更がゼロ**
   `git status --short` が空であること。
   変更が残っていれば、内容を確認したうえでコミットする。
2. **未送信の記録がゼロ**
   `git log @{u}..HEAD --oneline` が空であること。残っていれば送信する。
3. **引き継ぎメモに今回の内容が記載済み**
   `docs/agents/handover.md` の一番上が今回のセッションの内容になっていること。
   なっていなければ、`docs/agents/flow-map.md` の書式で1件追記し、
   `sh .claude/hooks/handover-trim.sh` を実行してからコミットして送る。
4. **提出中の変更の状態を明示**
   開いている提出物（PR）があれば、番号・題名・マージ可否を調べる。

## 提出中の変更が残っている場合

終了は妨げない。ただし**明示したうえで、マージするかを一度だけ尋ねる**。

> 提出中の変更が1件あります（#12「〇〇の追加」／衝突なし）。
> 先にマージしますか。不要であればこのまま終了できます。

利用者が「する」と答えたらマージし、その結果を4項目の確認に反映する。
「不要」または無回答のまま終了を求められた場合は、残っている旨を報告に明記して終了を認める。
勝手にマージしない。

## 満たせないとき

まず自分で解決を試みる（送信の再実行、衝突の解消など）。
それでも残る場合は **「終了できません」と明言**し、次を出す。

- 何が満たせていないか（項目名）
- なぜか（1〜2行、日常語で）
- どうすれば解決するか（利用者の操作が要るならその手順）

黙って「たぶん大丈夫」と言わない。

## 報告の形

全項目を満たしたときだけ、次の形で報告する。

> **セッションを終了して問題ありません。** この作業環境を破棄しても、失われるものはありません。
>
> 確認した項目:
> - 手元の未保存の変更: なし
> - 未送信の記録: なし
> - 引き継ぎメモ: 今回の内容を記録済み
> - 提出中の変更: なし（または「#12 が提出中のまま残っています」）
>
> 次回は「s」と打てば、続きから再開できます。

## 作業が何も無かった場合

雑談や質問だけで終わったセッションでは、引き継ぎメモを書かない。
中身の無い記録が溜まると、本当に必要な記録が押し出されるため。

> 記録すべき変更はありません。セッションを終了して問題ありません。
