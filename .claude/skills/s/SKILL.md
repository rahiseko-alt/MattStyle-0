# s — セッション開始の儀式

利用者は非エンジニア。前回どこまで進んだか、いま何が危険かを自分では判断できない。
このスキルが、開始時にその3点を代わりに提示する。

## 起動する場面

- 利用者が「s」「S」「/s」とだけ送ったとき
- 会話開始後、**最初の応答の冒頭**（利用者が `s` と打たなくても自動で出す）

一文字の「s」が明らかに別の意味に見える場合（前後に文がある、コードの一部など）は
通常どおり応答する。判断に迷ったときだけ「開始の合図でしょうか」と一度だけ尋ねる。

短い用件で開かれたときも報告は出す。ただし報告は先頭に置き、そのあと用件に答える。

## 手順

### 1. 調べる（読むだけ。書き込まない）

- `docs/agents/handover.md` の**一番上の1件** … 前回の「次にやること」と「未解決の問題」
- `git status --short --branch` … 手元に未保存の変更があるか、送信していない記録があるか
- `git log --oneline -3` … 直近で何をしたか
- 提出中の変更（PR）が開いていないか … `docs/agents/issue-tracker.md` の手順に従う

### 2. 報告する

次の3点だけを、この順で、簡潔に出す。表は使わない。

1. **前回の続き**: 残っている作業を1〜2行。無ければ「ありません」と書く
2. **いまの状態**: 未保存の変更／未送信の記録／提出中の変更の3つを、有無がわかる形で1行
3. **最初の一手**: 次にやることを1つだけ。利用者の操作が要るならその手順

例:

> **前回の続き**: 案内役が引き継ぎメモを読むかの確認が残っています。
> **いまの状態**: 未保存なし／未送信なし／提出中の変更なし。
> **最初の一手**: その確認をこの場で行います。

### 3. 続ける

「最初の一手」が私だけで済むもの（確認など）なら、その場で実行して結果まで報告する。
利用者の判断が要るものなら、そこで止めて指示を待つ。
